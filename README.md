# 刻舟录

明日方舟编年史。

《明日方舟》剧情的编年体史书，同人整理，非官方作品。按年分卷，纲目体，穿插原文片段，另有纪事本末（按事）和列传（按人）。

把国服的主线、活动（含活动隐藏剧情）、故事集和干员密录剧情整理成一个网页：

- **编年史**：全书二十九卷，从外纪到一一〇三年。见下文「编年史」。
- **纪事本末**：一件事一页，按事连读。索引可按时期、地区、性质、了局（已了、未了、悬案）筛选和分组。
- **列传**：一人一篇。索引可按出身、盖棺（盖棺定论、来日方长、生死未卜、异数）、族裔、所属、首见、身份筛选和分组。

- **时间轴**：竖向分叉时间线。最左边的灰线是主世界线；每个剧情组是一条故事线，从主世界线分出、结束时合回，同一时期并行的故事线并排显示。事件来自 PRTS「泰拉年表」，可按人物、地区势力、故事线和文字筛选，↑↓ 键逐条浏览。
- **剧情**：章节和活动目录 → 分集阅读（官方简介、出场人物、年表相关事件、剧本全文）。
- **人物**：干员档案、敌人图鉴里的 NPC 简介、出场剧情、相关事件、常同场人物。
- **博物志**：地理、势力、族裔、源石、科技、人文、生灵、远古八门的百科，按门列目录，可搜可筛。地理、势力两门列出全部地区势力，一地一页：条目正文在上，下面接层级、成员、相关事件、提及它的剧情；还没写正文的标「尚未成文」。每条底部有「书中提及」，统计编年史纲目和列传里写到它的地方。见下文「博物志」。
- **关系图**：只有人物、地区、势力（可选事件）；连线粗细是共同出场的集数，集数越多拉得越近。力导向布局持续运行：拖动节点时相连的节点跟着移动，悬停只看它的关联，改筛选时已有节点留在原处。中心力、斥力、连线力、连线距离可以调；可以以任意节点为中心查看。

## 数据来源与版权

- 剧本、干员档案、敌人图鉴：[Kengxxiao/ArknightsGameData](https://github.com/Kengxxiao/ArknightsGameData)，版权归鹰角网络。
- 年表事件：[PRTS「泰拉年表」](https://prts.wiki/w/泰拉年表)，CC BY-NC-SA 4.0。日期是社区根据剧情推测的，可能有偏差。
- 书外材料：设定集《大地巡旅》、官方影片、官方漫画、微博图文《泰拉记事》，版权归鹰角网络。原件和 OCR 全文放在 `Raw Data/`，不进 git，不进公开版；书里只录短引。

本地版网页（`site/`）有剧本全文，**只在本地使用，不要公开发布**。公开版由 `python -m pipeline.publish` 生成到 `dist/`，只含编年史和它引用的片段，去掉了剧本全文和干员档案正文，挂在 GitHub Pages 上。

## 使用

需要 Python 3.12+、git 和 curl，不依赖第三方 Python 库。所有命令在项目根目录运行。

```bash
python -m pipeline.fetch     # 下载/更新游戏数据（约 230MB），抓取 PRTS 年表（已缓存则跳过，--refresh-prts 强制更新）
python -m pipeline.build     # 解析全部剧情和年表，生成 site/data/（约 10 秒）
python -m pipeline.serve     # 在 http://127.0.0.1:8765 打开浏览器
python -m pipeline.check     # 年表出处对应情况、网页数据引用检查、需要人工处理的说话人
```

### 公开版

网页：<https://bbfutaba.github.io/arknights-chronicle/>。`python -m pipeline.publish` 把 `site/` 复制到 `dist/`，去掉剧本全文（`data/stories/`）和干员档案正文，然后把 `dist/` 推到 `gh-pages` 分支。公开版的编年史仍有引用的原文片段；剧情页只显示官方简介、出场人物和相关事件。

### 编年史

网页的「编年史」页按年分卷，「纪事本末」「列传」两页把同样的条目按事、按人连读，纲目体：每条先列纲（一句提要），再写目（始末），然后列人物和原文，最后是考异（默认折叠）。原文出处可以点开，在剧情页高亮被引的行。一件事散见各卷各月的，另有「纪事本末」页按时间连读。时间轴里的事件也能直接跳到编年史中的记述。

卷稿在 `data/annals/<年份>/`（一〇八〇年以前合为 `外纪`、`前纪甲`、`前纪乙`、`前纪丙` 四个目录，原文和年表都无年份的放 `不系年`），每个文件由若干 `@条 ev编号` 条目组成。引文只写出处指令（分集 id + 行号 + 锚点），不写原文；构建时程序从剧本里取出原文并核对锚点，月、日标题按 PRTS 年表的日期生成，同时报告漏写和重复的事件。收录以「对人或事有推力」为准：立条的条目要标明归属，即属于哪件纪事本末（`事:`）、哪篇列传（`传:`）；推力不足的标为附记（`附`，只书纲），没有推力的列入存目（`存目`，不入正文，卷末列目并写明理由）。系日以原文为本，原文与 PRTS 不合时改系（`系:1097-11-01`）；PRTS 漏列的事可以补条（`补:名称`）。列传在 `data/annals/列传.md`，人物页会显示此人的列传和编年史中的记述。`check` 和 `build` 会提示纲目里不合书法的用词。体例见 `data/annals/凡例.md`，写法见 `data/annals/写作规范.md`，纪事本末的划分和概述在 `data/annals/纪事本末.md`。

```bash
python -m pipeline.annals build                   # 检查并导出编年史（pipeline.build 结束时也会自动运行）
python -m pipeline.annals check <稿件路径>        # 检查一个稿件文件
python -m pipeline.annals show <分集id> [起 止]   # 带行号列出一集剧本
python -m pipeline.annals find "<正则>" [组id]    # 在剧本里搜索
```

导出的 `site/data/annals.json` 和 `annals/<年份>.md` 含剧本原文，不提交。

### 博物志

稿件在 `data/annals/博物志/*.md`，每条以 `@物 名字 门:… 别:… 关:…` 开头，再写 `【释】【说】【沿革】【见】【考异】`；格式和校验命令见 `data/annals/博物志须知.md`。`@引`、`@档` 和编年史一样严格校验，能点到剧情页；`@书`、`@影`、`@漫`、`@记` 是书外短引，到 `Raw Data/` 里的 OCR 全文做模糊比对，文件不存在就跳过。`python -m pipeline.annals build` 同时导出 `site/data/bowu.json`，只含编者文字和条目里写的短引，书外全文不进网页数据，也不进公开版。

  analyze.py       每集：出场人物、台词数、提及的地区势力

  linker.py        在事件描述里识别人物和地区势力

  site.py          导出 site/data/*.json
  annals.py        编年史和博物志：查剧本、取引文、校验、导出
  publish.py       生成公开版网页（dist/），去掉剧本全文和干员档案正文
  bundle.py        把网页打包成一个 HTML 文件：本地版（刻舟录-完整版.html，只在本地用）；加 --public 打包公开版（刻舟录-公开版.html，传到 GitHub Release）
  records.py       下载《泰拉记事》到 Raw Data/（经 PRTS，有间隔，遇 403/429 就停）
  comics.py        下载官方漫画到 Raw Data/
  ocr_gpu.py       书、影片、漫画、《泰拉记事》的 GPU OCR
data/
  raw/             游戏数据和 PRTS 缓存（git 忽略）
  curated/entities.toml  人工维护：别名、路人过滤、单字名字、补充的地区势力
  annals/          编年史卷稿（按年分目录）、纪事本末、凡例、写作规范、博物志（只含出处指令和短引，不含全文）

  index.html, style.css, js/   网页（原生 JS 模块，不需要打包）

## 剧情范围

| 分类 | 来源 | 组 id | 分集 id |
|---|---|---|---|
| 主线、活动、故事集 | `story_review_table`（游戏内「剧情回顾」） | `main_9`、`act13side` 等 | 游戏的 storyId，如 `act13side_level_act13side_01_beg` |
| 活动隐藏剧情 | `story_review_meta_table` 的活动档案，并入所属活动组、排在原有分集之后 | 所属活动 | `组id_剧本文件名`，如 `act13side_level_act13side_hidden_st01` |
| 干员密录 | `handbook_info_table` 的 `handbookAvgList`，一位干员一个组，组名是干员名 | 干员 id，如 `char_427_vigil` | 游戏的 storyId，如 `story_vigil_set_2_story_1` |
| 集成战略、生息演算、其他文本 | 原始 `story/` 目录里剧情回顾之外的文本（结局、月度记录、记录点、活动任务和手册），标题来自各数据表 | `rogue_4`、`sandbox_1`、`record_main_13` 等 | `组id_文件名` |

- 隐藏剧情游戏里没有关卡代号，按 PRTS 的写法编作 `NL-HD-1` 等，分集类型记作「幕间」。目前只有《长夜临光》的「逃离」「选择」「路漫漫」三篇。
- 干员密录的分集标题写作「干员名 · 密录标题」，一套分几篇的加「（1）」「（2）」。
- 新加的分集都排在原有分集之后、或在新组里，已有分集的 id 和行号不受影响，编年史卷稿的引文不用改。
- 不在范围内：肉鸽、生息演算、愚人节、教程和关卡内对话等剧本。

## 识别规则

- **说话人 → 人物**：先查 `entities.toml` 的 `[aliases]` 和编年史的 `data/annals/别名.md`（一人多名，合成一个人物页，如 Logos = 逻各斯、恩希欧迪斯 = 银灰），再匹配干员名；异格干员并入本体；「A&B」拆成两人，「阿米娅？」归到阿米娅；剧本选项算博士的台词。路人（「整合运动成员」「士兵A」）、以势力名说话的、「？？？」不建人物。
- **立绘**：对得上干员 id 的，没说话也算出场。
- **提及地区势力**：名字在一集台词和旁白里出现至少 2 次。
- **年表事件 → 人物/地区**：在事件描述里按名字最长优先匹配；单字名字只匹配 `[linker.single_char]` 里列出的，并跳过排除词。
- **年表出处 → 分集**：按「编号 标题/BEG|END|NBT」对应到本地分集，PRTS 的 BEG/END 分别是行动前/行动后；干员密录按「干员/干员密录/第几套[-第几篇]」对应。只出自干员密录的事件，故事线仍归「设定与档案」。

`python -m pipeline.check` 会列出疑似干员的说话人写法和被过滤的高频说话人，确认后写进 `entities.toml`。
