# 核对须知

项目：明日方舟编年史，《明日方舟》剧情的编年体史书。所有命令在项目根目录运行。全书写完后抽查四十条，四分之一有问题，多是压缩造成的：两个动作并成一句，先后或因果颠倒；主语压缩后指错了人；「当夜」「次日」「那天」把相对时间写实了；略掉了结果；引语改了字。你来逐条核对指定的文件，**只看条目能不能被原文证实，尽量找错**，不要因为读来通顺就放过。

先读 `data/annals/写作规范.md` 的「各字段」「书法」两节。

## 怎么核

对每一条立条（附记、存目跳过）：
1. 读【纲】【目】。从【原文】的 `@引` 找到分集，用 `python -X utf8 -m pipeline.annals show <分集id> [起 止]` 看；一条写到别的集的，用 `find "<词>" <组id>` 定位，或 `timeclues show <组id>` 看各集简介。不必通读全集，读到能核实每件事为止。干员档案：`python -X utf8 -c "import json;c=json.load(open('site/data/characters.json',encoding='utf-8'))['<名字>']['profile'];[print('##',s['title'],chr(10),s['text']) for s in c['sections']]"`。
2. 逐句核对事实：谁、做了什么、结果、先后、因果；胜负、生死是否说对；主语是否张冠李戴；「当夜」「次日」这类时间词原文是否支持；「」里的话是否一字不差。考异只核它引的话和说法，不必核全部。
3. **短引清单**：`python -X utf8 -m pipeline.annals quotes 短引.txt` 生成的清单 列出了全书里程序在剧本、档案、简介、年表文字中都找不到的「」短引（每行：卷、文件:行、条目、字段、引语）。你的文件里的每一处都要看：是改了字就改回原话，是概括就去掉引号改成转述，确实是别处（设定集、网页文案）的话就在考异注明出处。

## 怎么改

- **错**（原文明确不是这样）：就地用 Edit 改那一句，改到原文证实的程度。
- **过头**（原文没这么说，是推断却写成了事实）：改成原文说的程度，或在考异里加一句。
- 不加新内容，不润色没问题的句子，不压缩。不动 `@条` 行、`@引` 行、【人物】。书法用词照规范。
- 每改完一个文件运行 `python -X utf8 -m pipeline.annals check <文件>`，直到没有「!」和书法提示。**不要运行 `build`**。只改指定的文件。

## 交回的报告（中文，简短）

第一行：核了几条，无误几条，有错几条，过头几条，短引处理几处。然后逐条列「有错」的：编号、原句要点、原文（分集:行号）、怎么改的；「过头」的一条一句即可。核不了的如实写。不要编造结果。

## 附记怎么核

附记只书纲，没有目和 `@引`。它们多半转自 PRTS 年表，约六成的出处在本书数据之外（设定集《大地巡旅》《追溯泰拉》《求索泰拉》、泰拉记事、漫画、特别企划等）。清单里每条都列了年表原文和来源。逐条这样做：

1. **出处在数据里**（来源有分集或组，或是干员档案、模组、集成战略文本）：找到原文，核纲的每件事，核考异引的话和说法。
2. **出处在数据外**：原书核不了，但还有三件事可做。
   - 纲有没有超出年表的转述，有就收回到年表的程度。
   - 搜游戏文本找佐证或矛盾：`find` 只查剧本库，最多列八十条，不能单凭它写「剧本不载」；`python -X utf8 -m pipeline.annals rawfind "<词>"` 查全部原始文本；要看某个表的结构，再 Grep 查 `data/raw/ArknightsGameData/zh_CN/gamedata/`（`excel/` 下有 `uniequip_table.json` 模组、`enemy_handbook_table.json` 敌人档案、`item_table.json` 道具、`skin_table.json` 皮肤、`roguelike_topic_table.json` 集成战略等，`story/` 下有未收进剧本库的文本）。JSON 单行很长，用 `.{0,80}词.{0,80}` 这样的正则只取上下文。多换几个词搜，人名、地名、事名都试。
   - 考异要如实：写明出处，并写明未能核对原书。搜到佐证或矛盾就写上；原文与年表相违时以原文为准改纲，考异写明年表原话。
3. **断言也要核**：考异说「剧本不载」「原文不书年」的，搜过确实没有才能留，搜到了就改。「见某章」「见某条」的交叉引用要确实存在、确实那样说。
4. 「」里的话要一字不差，改了字的改回原话，概括的去引号。

只改清单里的附记，不动别的条目，不动 `@条` 行，不把附记扩成立条，不润色没问题的句子。

交回的报告（中文，简短）：第一行写核了几条、其中原文证实几条、出处在数据外几条（其中找到佐证几条、找到矛盾几条、无从印证几条）、有错几条、过头几条。然后逐条列有错的：编号、原句要点、依据（分集:行号或文件名）、怎么改的。过头的一条一句。另列两项，没有就写「无」：「系日有疑」（原文与系日不合，附依据，由主编决定改不改）；「或应立条」（你发现这条其实有明显推力，一句理由）。核不了的如实写，不要编造结果。
