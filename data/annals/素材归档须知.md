# 素材归档须知

项目：明日方舟编年史（`data/annals/`）。书外三类官方素材要归档，供整补和博物志使用：设定集《大地巡旅》、官方影片、官方漫画。原件和 OCR 全文都在 `Raw Data/`，这个目录不进 git。

## 分工

- **机器管全文**：本地 OCR 已经把全文转成文字，放在 `Raw Data/` 下。OCR 有错字，只作检索和阅读。
- **人管提炼**：归档文件是你自己的话写的摘要和事实，加少量短引。**不要逐字转录整页、整段或整话**，全文已有 OCR，重抄既费 token，也不该把别人的作品整部复写一遍。
- **短引**：只留真正值得引的话，一句一引，通常不超过三十字，同一节不超过三五句。引之前对照原图核对字词，因为 OCR 会错。

## 怎么读

- 先读 OCR 文字，弄清内容。只有这几种情况才看图：OCR 读不通、要引原话、要确认说话人、画面本身是信息（地图、图表、无字场面）、手写批注。
- 一条消息里并行读几张图，读完立刻把结论写进文件，再读下一批。旧图可能被上下文清掉，不要指望回头还能看。不要反复重读同一张。
- 人名按 `data/annals/人物对照表.md` 统一。认人靠称呼和自报姓名；认不准写「？（外貌）」，读完全篇后，只根据文字回填，不要为此重读图片。
- 分清**性质**并写明：叙述者的说法、人物台词、文件或报纸、宣传语、玩笑。别把一个人说的话写成事实。

## 归档文件的格式

每节一个小标题，下面按需写这几项，没有就省略：

```
## <节名> （页码或时间）
- 要点：这一节讲了什么，三五句。
- 事实：可系年的事、人物经历、制度、地理、数字，每条一行，后面注页码或时间戳。
- 年代线索：明写的年月，或能推出年代的话，注明是明写还是推断。
- 短引：「原话」（出处，谁说的）
- 对书：和编年史的关系。书里已有（文件:行）、书里没有、与书矛盾（双方怎么说）、可印证「未能核对」（文件:行）。
```

查书用 Grep 搜 `data/annals`（列传在 `列传.md`，以 `@传 名字` 开头），查游戏原文用 `python -X utf8 -m pipeline.annals rawfind "关键词"`，要在项目根目录运行。

## 规矩

- 只写归档文件，**不改 `data/annals` 里的书稿**，整补阶段统一改。
- 不做 git 操作，不运行 `pipeline.annals build`。
- 没把握的标明是推测。核不了的如实写，不要编造。
- 《序言组曲：火与路》对应的活动文本还没入库，它的归档只留作备用，不要据它提出改书。
- 联动活动不入正史。素材里出现联动内容，记一句「联动，不入正史」即可。

## 交回的报告（中文，简短）

归档文件路径；这部分对书最重要的发现，最多十条，先写最重要的；可印证或能改正「未能核对」的条目（文件:行）；没读完或没把握的部分。
