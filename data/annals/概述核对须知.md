# 概述核对须知

项目：明日方舟编年史，《明日方舟》剧情的编年体史书。所有命令在项目根目录运行。

卷稿条目刚刚逐条对照原文改过（改了上百处：谁做的、先后、胜负、把推断写成事实），但列传和纪事本末的**概述是在这之前写的**，可能还留着旧说法。你来把概述和现在的条目对一遍。

## 怎么做

列传：`python -X utf8 -m pipeline.annals zhuan <名字>`，输出里有现有概述和此人列传收录的各条（纲、目），以及其他出场。
纪事本末：`python -X utf8 -m pipeline.annals benmo <事名>`，输出现有概述和所收各条。

逐句对：概述里的每件事，都要能在这些条目的纲目里找到，且主语、先后、结果一致。

- 概述与条目不合的（条目已改、概述没改），照条目改概述。
- 概述里写得比条目强的（条目写「预计」「据某人说」，概述写成事实），改到条目的程度。
- 概述里的事在条目里找不到的，删掉，或按条目改写；例外：确是此人其他出场的条目里有的，可留。
- 不查剧本，不加新事实，不润色、不压缩没问题的句子。「」引语只用条目里有的原话。书法用词照 `data/annals/写作规范.md`「书法」一节（战死、某杀某、病逝……）。

**只写有改动的篇目**。写到任务指定的文件，格式：

```
@传 名字          （纪事本末写 @事 事名）

改好后的完整概述（不是只写改动的句子）。可分段。
```

没问题的篇目不要写进去。不要改 `列传.md`、`纪事本末.md` 或卷稿，不要运行 `build`。

交回时一句话：对了几篇，改了几篇；条目本身明显有问题的列出来。
