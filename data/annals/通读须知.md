# 通读须知（剧情回顾之外的文本）

项目：明日方舟编年史，《明日方舟》剧情的编年体史书。所有命令在项目根目录运行。全书写完后才发现，集成战略的结局与月度记录、生息演算、主线记录点、活动里的任务和手册这些文本没有收进剧本库，也没有系统读过。现在它们已经入库（分类「集成战略」「生息演算」「其他文本」，`show`、`find`、`@引` 都可用）。你来通读其中一批，写丛目，找出书里漏记的事和该改的地方。**不改任何卷稿、列传、纪事本末**，只写你自己的丛目文件。

先读 `data/annals/写作规范.md` 的「推力」和「系日以原文为本」两节，以及 `data/annals/凡例.md`。

## 怎么读

任务给你一个通读文件，每集有 `## 分集id  标题` 的标题，每行开头是 `show` 的行号（连续重复的台词已略去）。用 Read 分段读完整个文件，不要跳读，不要只靠搜索。读不完的如实写明读到哪里。

- `python -X utf8 -m pipeline.annals show <分集id> [起 止]`：看某集原文。
- `python -X utf8 -m pipeline.annals find "<正则>" [组id]`：搜剧本库，最多列八十条。
- `python -X utf8 -m pipeline.annals rawfind "<正则>"`：搜全部原始游戏文本，含数据表里的模组、敌人档案、收藏品文案。
- 查书里有没有写过：Grep `data/annals`（排除 `丛目`），列传在 `data/annals/列传.md`，纪事本末在 `data/annals/纪事本末.md`。

## 先判性质

这些文本里虚构很多，每条候选都要判明：

- **实事**：作为真实发生的事呈现，包括档案、手册、日记、信件、通讯。
- **转述**：剧中人的说法、传说、史书记载，未必属实。
- **虚构**：梦境、寓言、推演、玩法设定、「如果」式的结局、只写给玩法用的台词。不是泰拉世界里真实发生的事，就明说。愚人节活动默认虚构。

拿不准就写拿不准和理由，不要猜。集成战略的结局和分形索引要特别小心：同一事件常有互斥的几个结局，这样的不能当实事。

## 筛选

只列有推力的（事之因果、人之成长、世界格局）。先问：删掉这一条，读者会看不懂后面的哪件事、哪个人吗？世界观设定、气氛描写、玩法说明、无关大局的小故事都不列。宁少勿滥，但确实推动了人或事的不要漏。

## 写什么

写到任务指定的文件 `data/annals/丛目/壬-<批名>.md`，格式如下：

```
# 丛目 · 壬 · <批名>

通读范围和读完情况，一两句。这批文本总体是什么性质，一两句。

## 候选

### 1. 一句话写清这件事
- 出处：分集id:行号
- 性质：实事 / 转述 / 虚构
- 时间：原文依据（写原话），推得的系年；没有依据写「不系年」
- 推力：哪一类，具体推动了什么事、塑造了谁
- 现状：书里已有（编号，文件:行，写到什么程度）或没有
- 建议：补条（归属 事:… 传:…）/ 并入 ev… 的目 / 附记 ev… 升立条 / 只补考异 / 不录

## 更正

现有条目被这批文本证实或推翻的。写明编号、文件:行、原句要点、依据（分集id:行号）、该怎么改。「剧本不载」「原文不书」说错了的都算。
```

纪事本末和列传的名字要用书里现有的：`grep "^@事" data/annals/纪事本末.md`、`grep "^@传" data/annals/列传.md`。原话引用要一字不差。

## 交回的报告（中文，简短）

第一行：通读了多少集，读完没有；候选几条（补条、并入、升立条、只补考异各几条）；更正几条。然后列最重要的三到五条，每条一句。不要编造结果。
